## [0.1.0] - 2026-09-27

### Features

- **core**: Read menu bar items through Accessibility and rank them

  Scans every app's AXExtrasMenuBar off the main thread, names Apple's agents,
  tells visible items from ones behind the overflow arrow or the notch, and ranks
  by fuzzy match plus frecency with a favourite boost.

- **bar**: Mark, tray model and moving icons

  The mark keeps itself the rightmost app icon. Opening an item reaches it
  wherever it is: pressed in place, through macOS's overflow arrow, or moved from
  under the notch and put back. Favourites are dragged next to the mark.

- **palette**: Dropdown under the mark

  Non-activating glass panel that lists what's out of sight, most used first;
  typing searches every icon. Enter or Cmd-1..9 opens, Cmd-P favourites.

- **settings**: Keyboard-first glass settings

  j k or arrows choose, Enter changes, h goes back. Favourites list of tray apps
  open now, reassignable shortcut, About with Support Ukraine and credits.

- **app**: App wiring, global shortcut and updates

  Carbon hotkey (Ctrl-Opt-T by default), open at login, Sparkle updates as the
  only network access, Accessibility onboarding and restart when needed.

- **landing**: Landing page and update feed

  Static page with no third-party requests: find, reach and favourite menu bar
  icons, what macOS 27 changed, privacy, Support Ukraine. Hosts appcast.xml.

### Build and dev environment

- **app**: XcodeGen project and build configuration

  Swift 6 with MainActor isolation, hardened runtime, Sparkle 2. Ad-hoc signing by
  default; a gitignored Signing.xcconfig adds the team for stable Accessibility
  grants. Icon rendered from code.

- **release**: Notarized DMG, Sparkle appcast and GitHub release

  task release bumps the version from commits, notarizes the DMG, signs the
  appcast entry, tags vX.Y.Z and attaches Trayfinder.dmg to the GitHub release.

- **release**: Add the Sparkle public key (#8)

  ## Why
  Release builds only check for updates when the Sparkle public key is
  set.
  
  ## What changed
  - `SPARKLE_PUBLIC_KEY` in `app/Config/Sparkle.xcconfig` (public half
  only; the private key is in the owner's keychain).
  
  ## Checked
  - [x] Key generated with `task app:sparkle:keys`


### CI

- Checks, PR title rule, auto labels and Dependabot

  CI always reports app and landing checks, PR titles must be Conventional
  Commits (they become squash commits), labels by area and type.

- Split the PR title check from labelling

  The title check runs on pull_request so it reports on the PR's head commit and
  can be required. Labelling stays on pull_request_target to label fork PRs.
